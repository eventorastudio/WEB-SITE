# 05 - Memory System

## Propósito

Este documento describe el funcionamiento del Sistema de Memoria Conversacional de Aura.

Su objetivo es mantener el contexto entre los mensajes del cliente para ofrecer conversaciones naturales, coherentes y continuas.

La memoria almacena únicamente información relevante sobre la conversación y el cliente.

La memoria nunca reemplaza la Base de Conocimiento de Eventora Studio.

---

# Objetivos

El Sistema de Memoria debe ser capaz de:

- Recordar información relevante del cliente.
- Mantener el contexto durante toda la conversación.
- Evitar preguntas repetidas.
- Complementar la búsqueda del Motor RAG.
- Facilitar conversaciones naturales.
- Actualizar la información cuando sea necesario.
- Descartar información irrelevante.

---

# Ubicación dentro del Pipeline

```
Extractor de Entidades
        │
        ▼
Memoria Conversacional
        │

Motor RAG
```

---

# Responsabilidad

El Sistema de Memoria administra toda la información conocida sobre la conversación actual.

Este módulo no interpreta documentos ni responde preguntas.

Su responsabilidad consiste únicamente en recuperar y actualizar contexto.

---


# ¿Qué almacena la memoria?

La memoria únicamente conserva información útil para futuras interacciones.

Ejemplos:

- Nombre del cliente.
- Tipo de evento.
- Fecha del evento.
- Ciudad.
- Número aproximado de invitados.
- Paquete de interés.
- Paquete contratado.
- Método de pago seleccionado.
- Estado del proyecto.
- Preferencias del cliente.

Toda la información almacenada debe aportar valor a conversaciones posteriores.

---

# ¿Qué NO almacena?

La memoria no debe almacenar:

- Documentación de Eventora Studio.
- Políticas.
- Información obtenida desde el Motor RAG.
- Respuestas completas del modelo.
- Conversaciones irrelevantes.
- Información temporal sin utilidad futura.

La información oficial siempre debe consultarse desde la Base de Conocimiento.

---

# Tipos de Memoria

Aura utiliza diferentes tipos de memoria.

## Memoria de Conversación

Información obtenida durante la conversación actual.

Ejemplos

```
Cliente:
Mi boda será en diciembre.

↓

La memoria registra:

Evento:
Boda

Fecha:
Diciembre
```

---

## Memoria del Cliente

Información permanente o de largo plazo que continúa siendo útil durante futuras conversaciones.

Ejemplos

```
Cliente:

Luis

↓

Evento favorito

↓

Paquete contratado

↓

Ciudad
```

La información almacenada dependerá de las políticas definidas por el sistema.

---

## Memoria de Estado

Representa el estado actual del proceso comercial.

Ejemplos

```
Solicitando información

↓

Comparando paquetes

↓

Esperando pago

↓

Proyecto en diseño

↓

Cambios solicitados

↓

Proyecto finalizado
```

Esta información permite que Aura adapte sus respuestas según la etapa del cliente.

---

# Recuperación de Contexto

Antes de consultar la Base de Conocimiento, Aura recupera la memoria disponible.

Ejemplo

Memoria

```
Evento:
Boda

Fecha:
14 de diciembre

Invitados:
180
```

Nuevo mensaje

```
¿Cuánto cuesta?
```

Aura ya conoce el contexto y puede utilizarlo durante la búsqueda de documentos sin volver a solicitar la misma información.

---

# Actualización de Memoria

Después de procesar cada mensaje, Aura decide si existe información relevante que deba almacenarse.

Ejemplo

Mensaje

```
Creo que me quedaré con el paquete Premium.
```

La memoria actualiza:

```
Paquete de interés:

Premium
```

No toda la información debe almacenarse.

---

# Reemplazo de Información

Si el cliente modifica información previamente conocida, la memoria debe actualizar el valor existente.

Ejemplo

Antes

```
Invitados

150
```

Cliente

```
Ahora serán 180 invitados.
```

Después

```
Invitados

180
```

La memoria siempre debe conservar la información más reciente.

---

# Eliminación de Información

Cuando un dato deja de ser válido, deberá eliminarse o reemplazarse.

Ejemplo

```
Cancelar evento

↓

Eliminar fecha

↓

Eliminar invitados

↓

Actualizar estado
```

El objetivo es mantener un contexto consistente.

---

# Relación con el Motor RAG

La memoria no reemplaza la búsqueda documental.

Su función consiste en enriquecer la consulta que será enviada al Motor RAG.

Ejemplo

Consulta

```
¿Cuánto cuesta?
```

Sin memoria

```
Consulta incompleta.
```

Con memoria

```
Evento:
Boda

Invitados:
180

Paquete:
Premium
```

El Motor RAG utiliza este contexto para recuperar documentos más relevantes.

---

# Responsabilidades

El Sistema de Memoria debe:

- Recuperar contexto.
- Actualizar información.
- Reemplazar datos obsoletos.
- Eliminar información inválida.
- Mantener consistencia.
- Proporcionar contexto al Motor RAG.

---

# Restricciones

El Sistema de Memoria NO debe:

- Consultar documentos oficiales.
- Generar respuestas.
- Interpretar políticas.
- Ejecutar herramientas.
- Inventar información.
- Reemplazar la Base de Conocimiento.

Toda información oficial pertenece exclusivamente al Motor RAG.

---

# Consideraciones

Una memoria mal administrada puede provocar:

- Preguntas repetidas.
- Contexto inconsistente.
- Recuperación incorrecta de documentos.
- Respuestas poco naturales.
- Información obsoleta durante la conversación.

Por ello, la memoria debe almacenar únicamente información relevante, consistente y vigente.
